# Standardizing Environment Variables Across Stacks

## Current State

You have two init scripts that handle environment setup:
- `stacks/init_env.sh` — generates `.env` files for stacks that need them
- `stacks/init_data.sh` — initializes persistent data directories

However, **there's no clear documentation** on:
- Which stacks need `.env` files vs. hardcoded config
- How to handle sensitive values (passwords, API keys)
- How to rotate secrets across all stacks at once
- How to distinguish between host-specific and global variables

## Recommended Standard

### Per-Stack Pattern

Each stack should follow this layout:

```
stacks/SERVICE/
├── docker-compose.yml          (always git-tracked)
├── .env                         (git-ignored; generated by init_env.sh)
├── .env.example                 (template for manual setup)
└── config/                      (optional; config files)
    └── service.yml
```

### Types of Variables

#### 1. **Global Variables** (same across all hosts)
- Service versions, default settings
- Place in `.env.example`, check into git

Example:
```env
SERVICE_VERSION=1.2.3
LOG_LEVEL=info
```

#### 2. **Host-Specific Variables** (docker.lan vs. octoprint vs. proxmox)
- Storage paths, host-specific IPs
- Pulled from `ansible/group_vars/` or `ansible/inventory.yml`
- Reference in docker-compose.yml:
  ```yaml
  environment:
    - STORAGE_PATH=${STORAGE_PATH}  # Provided by ansible or .env
  ```

#### 3. **Secrets** (passwords, API keys, tokens)
- Never commit to git
- Source from Ansible `secrets.yml` or `.env` file
- Regenerate/rotate periodically

Example:
```env
PLEX_CLAIM_TOKEN=claim-xxxxx
ADMIN_PASSWORD=supersecret
API_KEY=sk-xxxxx
```

### Generating .env Files

#### Option A: init_env.sh (Current)
- Advantage: Centralized, one-time setup
- Disadvantage: Can't easily rotate/update individual stacks

**Better approach:**
```bash
#!/bin/bash
# stacks/init_env.sh

# Template for each stack
declare -A STACKS=(
    [adguardhome]="DEFAULT_DNS_UPSTREAM"
    [docker-registry]="REGISTRY_PASSWORD"
    [plex]="PLEX_CLAIM_TOKEN PLEX_ALLOWED_NETWORKS"
)

for STACK in "${!STACKS[@]}"; do
    ENV_FILE="$STACK/.env"
    if [ ! -f "$ENV_FILE" ]; then
        echo "Creating $ENV_FILE"
        cat > "$ENV_FILE" << EOF
# Copy from .env.example and fill in values
$(cat "$STACK/.env.example")
EOF
        chmod 600 "$ENV_FILE"
    fi
done
```

#### Option B: Ansible-Driven (Recommended for future)
- Generate `.env` files as part of Ansible playbook
- Automatically pull from `secrets.yml`
- Easier to rotate secrets and redeploy

Example Ansible role:
```yaml
# ansible/roles/generate_env/tasks/main.yml
- name: Generate .env file from template
  template:
    src: env.j2
    dest: /path/to/stack/.env
    mode: '0600'
  vars:
    plex_claim_token: "{{ secrets.plex_claim_token }}"
    admin_password: "{{ secrets.admin_password }}"
```

## Secrets rotation
To update all secrets:
1. Update `ansible/secrets.yml`
2. Run init_env.sh to regenerate .env files
3. Redeploy: `docker-compose down && docker-compose up -d`
```

### 3. Update `init_env.sh` to be Clearer

```bash
#!/bin/bash
# stacks/init_env.sh - Generate .env files from .env.example templates

STACKS_DIR="$(dirname "$0")"

for stack_dir in "$STACKS_DIR"/*/.env.example; do
    if [ -f "$stack_dir" ]; then
        stack_name=$(dirname "$stack_dir")
        env_file="${stack_name}/.env"
        
        if [ ! -f "$env_file" ]; then
            cp "$stack_dir" "$env_file"
            chmod 600 "$env_file"
            echo "Created $env_file - please edit with actual values"
        else
            echo "Skipped $env_file (already exists)"
        fi
    fi
done
```

### 4. Document in Root README.md

Add to main README:

```markdown
## Configuration

### Environment Variables

Each service stack may require environment variables:

1. **First-time setup:**
   ```bash
   cd stacks/
   ./init_env.sh          # Creates .env files from templates
   # Edit each .env file with actual secrets/passwords
   ./init_data.sh         # Initialize data directories
   ```

2. **Rotating secrets:**
   - Update `ansible/secrets.yml`
   - Run `./init_env.sh` again (skips existing files; delete to regenerate)
   - Redeploy affected stacks: `cd SERVICE && docker-compose up -d`

3. **Checking what's configured:**
   ```bash
   ls stacks/*/.env       # Lists all configured stacks
   ```
```
